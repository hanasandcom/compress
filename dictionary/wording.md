# Wording examples

Use these pairs to spot wording that says little and replace it with language that
says what happened. Follow the project's own voice. These are examples, not a word
replacement list: do not use the suggested wording when it is inaccurate or does not
fit the context.

| Avoid | Prefer |
| --- | --- |
| Evidence-backed review | Analysis supported by research |
| Leverage existing functionality | Reuse the existing feature |
| Unlock the full potential | Let users do [specific task] |
| Seamlessly integrate | Connect [A] to [B] |
| Robust solution | [Name the behavior or guarantee it provides] |
| Enhance the user experience | Let users [specific action] more easily |
| It is worth noting that… | [State the point directly] |
| A comprehensive set of improvements | [Name the changes that matter] |
| This is not just X; it is Y | [Say what it is and why it matters] |

Do not add wording just to make a response, README, label, or feature sound polished,
unique, or human. Do not run a detector or rewrite text to evade one. Prefer a concrete
claim that can be checked, and leave out claims that add no useful information.
